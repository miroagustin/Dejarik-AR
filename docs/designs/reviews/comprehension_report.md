### What this proposes
This is an augmented-reality board game for a university computer-vision course project. The demo is on 26/11/2026, shown live over a Teams screen share. A webcam on a tripod films a printed circular board that has 12 ArUco markers around its rim. A Python process on the host's PC does all the thinking: it estimates the board pose (IPPE solvePnPGeneric, LM refinement, One-Euro filter), tracks the hand with MediaPipe, enforces the rules and runs a heuristic CPU opponent. For each frame it sends the browser the JPEG, the pose for that same frame and any game-state changes over one local WebSocket. A Three.js page draws the video, animated hologram creatures, the HUD and effects, and sends back only clicks, keys and animation-done acks. Player 1 is one of three things, switchable live with `P`: the CPU, the host playing both sides, or a remote person. The remote person joins through a cloudflared quick tunnel with a token link, watches a 480p copy of the same AR video and clicks to play. The detailed plan lists 43+ files with an owner each, a 24-day calendar with checkpoints ("controles") and a verification plan. Creature models are generated by an AI driving Blender, checked by a mechanical validator.

### How the existing system works, per this document
Nothing has been built yet. The document says the repo holds only `Dejarik_AR_Brief.pdf`, `concepts_brief.md` and this document, so every file is new (line 764). The only earlier system it mentions is the group's last project: Yu-Gi-Oh cards fighting on loose ArUco markers, which the professor judged "precario" (line 53). The team is one leader who knows Blender, Three.js and Unity, plus four Python developers.

## Findings

### 1. 🟡 Major: The game action vocabulary is given three different ways (lines 381–383 vs 953 vs 963)
The action sets disagree:
- The Technical Plan defines `select(cell)` and `target(cell)`.
- `hands.py` enqueues `("target_or_select", cell)`.
- `game.py`, the AI and transport use `("tap", cell)` and `("reset",)`.

A reader cannot tell which one is the contract.

**Suggested change:** In "Juego (autoridad)", define `("tap", cell)`, which resolves select, move, attack or deselect from the current state, plus `("reset",)`. Change line 953 to `("tap", cell)`.

### 2. 🟡 Major: A Python restart breaks the remote link (lines 183, 708)
CUJ 4 says both browsers reconnect on their own. But a new token is generated on every start, and a new `cloudflared` gives a new quick-tunnel URL. The remote player's old link therefore stops working.

**Suggested change:** Do one of the following, and in both cases state the expected recovery time:
- Persist the token and keep `cloudflared` alive (or reuse it) across `--resume`.
- Change CUJ 4: the host's browser reconnects on its own, and the remote player gets a new link through the Teams chat.

### 3. 🟡 Major: Switching into `remote` with `P` is undefined (lines 34, 251, 482, 905)
`cloudflared` starts only with `--mode remote`, yet `P` cycles into `remote`. The doc does not say what happens in that case, or what the HUD shows when no tunnel exists.

**Suggested change:** When `P` enters `remote` and no tunnel is running, call `tunnel.start()`. Show "Abriendo túnel…" / "Túnel no disponible" in the HUD. State the full cycle: cpu → remote → local → cpu.

### 4. 🟡 Major: The `--remote` flag does not exist (line 197)

**Suggested change:** Change line 197 to `--mode remote`.

### 5. 🟡 Major: The fallback chain cannot be paraphrased (line 93)
